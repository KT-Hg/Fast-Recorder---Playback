    Câu truy vấn được tách token và phân tích thành cây cú pháp, rồi rút gọn thành một mô hình phẳng: các điều kiện lá được đánh số, danh sách join, phần gom nhóm, sắp xếp và phân trang. Bốn kỹ thuật chạy trên mô hình đó.

    EP + BVA

    Phân hoạch tương đương (Equivalence Partitioning) chia miền giá trị của mỗi điều kiện thành các lớp mà câu truy vấn đối xử như nhau, rồi lấy một giá trị đại diện cho mỗi lớp. Phân tích giá trị biên (Boundary Value Analysis) bổ sung những giá trị mà lỗi lệch một đơn vị thực sự nằm ở đó — chính giá trị biên và hai giá trị kề nó. Bước nhảy theo kiểu dữ liệu suy được: 1 với số nguyên, 0.01 với tiền tệ, một ngày với kiểu date, một giây với timestamp. Cột chuỗi không có giá trị liền kề dạng số, nên case biên của chúng xoay quanh độ dài, chuỗi rỗng và khoảng trắng.

    Bảng quyết định + độ phủ

    Mệnh đề WHERE là một biểu thức logic, nên các luật của nó chính là một bảng quyết định: mỗi điều kiện một cột, mỗi tổ hợp một dòng. Trong ngưỡng cấu hình, bạn nhận đủ bảng 2ⁿ. Vượt ngưỡng, công cụ chuyển sang MC/DC — với mỗi điều kiện, một cặp luật giống hệt nhau ngoại trừ điều kiện đó, và việc lật riêng nó làm đổi kết quả chung. Điều kiện nào không tìm được cặp như vậy sẽ bị báo cáo: nó không thể tác động độc lập lên kết quả, thường nghĩa là thừa hoặc sai logic. Biểu thức CASE được phủ theo nhánh, bao gồm cả nhánh NULL ngầm định khi thiếu ELSE.

    NULL & logic 3 trạng thái

    Điều kiện trong SQL trả về TRUE, FALSE hoặc UNKNOWN, và chỉ TRUE mới giữ lại dòng. Kỹ thuật này chỉ đích danh giá trị NULL đứng sau từng hành vi: status <> 'x' làm rơi mất các dòng NULL, NOT IN trả về rỗng khi subquery sinh ra NULL, COUNT(col) lệch với COUNT(*), khoá join mang NULL không bao giờ khớp, khoá gom nhóm NULL gộp thành một nhóm, và vị trí NULL trong ORDER BY khác nhau tuỳ hệ quản trị.

    JOIN / GROUP BY / ORDER-LIMIT

    Nơi lỗi nằm ở hình dạng kết quả chứ không phải ở một giá trị: mỗi join được test ở ba mức lực lượng 1:1, mồ côi và 1:n; một điều kiện WHERE đặt trên bảng thuộc outer join âm thầm biến nó thành inner join; nhóm rỗng, một nhóm và nhiều nhóm; các dòng bằng nhau trong ORDER BY; và các trang ở mức bằng, dưới, vượt quá số dòng thực có.

    Giá trị mẫu

    Mọi giá trị trong kết quả hoặc là đọc được từ câu truy vấn, hoặc là do công cụ tự nghĩ ra. Những giá trị tự nghĩ ra được gom hết vào bảng Giá trị mẫu ở cột trái: các tham số truyền vào (:amount, ?) mà câu truy vấn không cho biết giá trị, và giá trị lấp chỗ trống cho những cột không bị điều kiện nào ràng buộc. Sửa một ô ở đó là toàn bộ case và dữ liệu mẫu dùng giá trị ấy được sinh lại theo, thay vì phải sửa từng case một.

    Tham số một khi đã có giá trị sẽ được coi như hằng số viết thẳng trong câu lệnh, nên age >= :min với :min = 18 cho ra đúng bộ biên 17 / 18 / 19 chứ không còn ghi :min - 1. Các cột khoá chính và khoá ngoại cố tình không cho sửa: chúng là thứ nối các dòng dữ liệu với nhau, ghi đè lên là hỏng chính cái join mà dữ liệu mẫu sinh ra để kiểm thử. Vì những giá trị này không nằm trong câu truy vấn, chúng được báo ngay phía trên danh sách case.

    Những giới hạn nên biết

    • Chỉ câu lệnh ngoài cùng được phân tích. Hãy dán riêng từng CTE hoặc subquery để có bộ case riêng.
    • Không có lược đồ bảng, nên kiểu cột được suy từ giá trị so sánh trước, tên cột sau. Khi cả hai đều không quyết định được, giá trị biên chỉ là chỗ điền tạm và case sẽ nói rõ điều đó.
    • Kết quả mong đợi mô tả điều mà ngữ nghĩa SQL bắt buộc, không phải điều dữ liệu hiện tại của bạn đang có.

    The query is tokenised and parsed into a statement tree, then reduced to a flat model: numbered leaf conditions, join list, grouping, ordering and paging. Four techniques run over that model.

    EP + BVA

    Equivalence Partitioning splits each predicate's input domain into classes the query treats the same way and takes one value from each. Boundary Value Analysis adds the values where off-by-one defects live — the boundary and its two neighbours. The step size follows the inferred type: 1 for an integer, 0.01 for money, a day for a date, a second for a timestamp. String columns have no numeric neighbour, so their boundary cases are about length, empty string and whitespace instead.

    Decision Table + Coverage

    The WHERE clause is a boolean expression, so its rules are a decision table: one column per condition, one row per combination. Up to the configured limit you get the full 2ⁿ table. Past it, the tool switches to MC/DC — for each condition, a pair of otherwise-identical rules where flipping only that condition flips the result. A condition with no such pair is reported: it cannot independently affect the outcome, which usually means it is redundant or the logic is wrong. CASE expressions get branch coverage, including the implicit NULL branch a missing ELSE leaves behind.

    NULL & 3-valued logic

    SQL predicates return TRUE, FALSE or UNKNOWN, and only TRUE keeps a row. This technique names the specific NULL behind each behaviour: status <> 'x' dropping NULL rows, NOT IN returning nothing when the subquery yields a NULL, COUNT(col) disagreeing with COUNT(*), NULL join keys never matching, NULL grouping keys collapsing into one group, engine-specific NULL placement in ORDER BY.

    JOIN / GROUP BY / ORDER-LIMIT

    Where the defect is in the shape of the result rather than a value: each join tested at 1:1, orphan and 1:n cardinality; a WHERE predicate on an outer-joined table silently turning it into an inner join; empty, single and multiple groups; ties in ORDER BY; and pages at, below and beyond the row count.

    Sample values

    Every value in the results is either read from the query or invented by the tool. The invented ones are collected into the Sample values panel on the left: the bind parameters (:amount, ?) whose value the query does not carry, and the filler used for columns no predicate constrains. Editing one there re-runs generation, so every case and every fixture row that uses it changes together rather than case by case.

    A parameter with a value is treated as a literal written into the statement, so age >= :min with :min = 18 produces the real 17 / 18 / 19 boundary trio instead of :min - 1. Primary and foreign keys are deliberately not editable: they are what links the fixture rows to each other, and typing over them breaks the very join the fixture exists to exercise. Because these values are not in the query text, they are reported above the case list.

    Limits worth knowing

    • Only the outer statement is analysed. Paste a CTE or a subquery separately for its own cases.
    • There is no schema, so column types are inferred from comparison literals first and column names second. When neither settles it, the boundary value is a placeholder and the case says so.
    • Expected results describe what the SQL semantics require, not what your data currently contains.
